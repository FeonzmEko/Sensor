打点标签里有 `开始步行` / `结束步行`、`进入电梯` / `离开电梯` 这类**成对事件**，

## 4. 手写时域四件套

对每个窗口分别计算三轴与合矢量特征（`window_features.csv`）：

- **均值** `mean = (1/N) Σ xᵢ`，主要反映重力与姿态；
- **方差** `var = (1/N) Σ (xᵢ − mean)²`（总体方差，`ddof = 0`），反映波动强度；
- **过零率**：去均值后统计符号变化次数，`ZCR = 过零次数 / 时长`（此处按秒计），可选 FFT 带限；
- **峰值**：`peak_dynamic = max|xᵢ − mean|`，同时保留 `peak_raw`。

全段统计：合矢量方差 min = 0.016、median = 9.232、max = 42.240；
全段动态峰值最大 56.51 m/s²（出现在骑行段）。对应图：`figures/time_features.png`。

**特征分工与局限**（用本会话的分状态数据验证）：

| 结论 | 证据 |
|---|---|
| 方差判“动没动”有效 | 静止 0.102 / 电梯 0.148 ↔ 步行 10.212 / 楼梯 5.657 |
| 均值对运动强度基本失明 | 各状态合矢量均值都在 9.7~10.2 m/s²，只反映重力与姿态 |
| ZCR 反映“动多快”，但短窗最吃亏 | 骑行 51.75 次/秒 vs 步行 4.50 次/秒；`W = 0.5 s` 时计数粒度只有 2 次 |
| 峰值判“动多大”会被非步行活动抬高 | 骑行动态峰值 11.09 > 步行 8.50 |
| 时域相近但节奏不同 → 仍需频域 | 骑行与步行的合矢量幅度同量级，但骑行能量集中在 3 Hz 以上（`R = 0.105`） |

## 5. FFT 主峰与步频

- 对每个窗口先去除直流分量、加汉宁窗（幅值按相干增益补偿），计算单边频谱，
  在 `0.5 ~ 3 Hz` 行人步频带内查找主峰；
- 频率分辨率 `Δf = fs / N = 1 / W = 0.25 Hz`，因此**步频读数只能落在 15 步/分的格点上**；
- 步频换算：`step_frequency_spm = f_peak × 60`。

分状态结果：

| 状态 | 主峰步频中位数 / 步·分⁻¹ | 窗口数 |
|---|---:|---:|
| 步行 | 120.0 | 398 |
| 楼梯 | 120.0 | 66 |
| 骑行 | 135.0 | 82 |

全段主峰步频中位数 120.0 步/分（P05 45.0、P95 165.0），与步行段一致；
骑行段的主峰抬到 135.0 步/分，是踏频（约 2.25 Hz）而不是步频。

### 5.1 FFT 主峰与峰间距法对比

同样的窗口再用**峰间距法**（带通后数相邻峰间隔，`步频 = 60 / 平均间隔`）独立算一遍：

| 状态 | FFT 主峰步频 / 步·分⁻¹ | 峰间距法步频 / 步·分⁻¹ | 差值 |
|---|---:|---:|---:|
| 步行 | 120.0 | 117.5 | 2.5 |
| 楼梯 | 120.0 | 117.8 | 2.2 |
| 骑行 | 135.0 | 139.2 | 4.2 |
| 电梯 | 105.0 | 134.3 | 29.3 |

差异来源：FFT 的读数被 `Δf = 0.25 Hz`（= 15 步/分）的格点量化，峰间距法给出连续值，
所以两者相差不到一个格点（2~4 步/分）属于正常；而电梯段的 29.3 步/分说明
**两种方法在“没有真实步态节奏”的段上给出的数值都不可信**——电梯里没有人在走路，
105 或 134 步/分都是噪声被强行解释成节奏。

### 5.2 慢走 / 快走的说明

本会话的步行段节奏**高度一致**（峰间距频率均值 1.96 Hz，四分位 1.94~1.98 Hz），
因此无法在这条数据里构造真正的“慢走 vs 快走”对比。作为替代，报告给出
**步行 vs 骑行**的时域 / 频域并排图（`figures/walk_vs_bike_spectrum.png`）：
两段的合矢量幅度同量级（步行峰值约 18、骑行约 16 m/s²），
但步行的能量集中在一个 1.75~2.0 Hz 的尖峰上，骑行的能量铺开到 3 Hz 以上、主峰跑到 10.25 Hz。
这既解释了“时域特征相近但节奏不同”，也解释了作业②的 `R` 为什么能拉开差距。

其他局限：本会话没有出现“主峰跑出步频带”的异常，说明 `fs = 115 Hz` 远高于奈奎斯特要求，
与 D07 的混叠失效形成对照。

对应图：`figures/fft_spectrum.png`、`figures/time_frequency.png`；频谱数据 `spectrum.npz`。

## 6. D06 参数实验场

固定同一段数据，只改窗长与步进（`d06_window_sweep.csv`、`figures/d06_window_sweep.png`）：

| 窗长 W / s | 方差均值 | 方差标准差 | ZCR 均值 | ZCR 标准差 | 动态峰值均值 |
|---:|---:|---:|---:|---:|---:|
| 0.25 | 5.13 | 4.67 | 7.65 | 4.08 | 3.83 |
| 0.50 | 8.08 | 5.25 | 6.18 | 3.57 | 5.46 |
| 1.0 | 8.25 | 4.96 | 6.37 | 3.32 | 6.21 |
| 2.0 | 8.36 | 4.67 | 6.37 | 3.03 | 7.00 |
| 4.0 | 8.55 | 4.24 | 6.11 | 2.46 | 7.88 |
| 8.0 | 8.97 | 3.58 | 5.81 | 1.88 | 9.09 |
| 16.0 | 9.14 | 2.78 | 5.71 | 1.10 | 9.97 |

结论：窗长越短，方差与 ZCR 的抖动越大（`W = 0.25 s` 时方差标准差 4.67，是 `W = 16 s` 的 1.7 倍）、
噪声越被放大；窗长越长，方差被平均钝化（从 8.25 缓到 9.14），动态峰值反而被大冲击抬高
（3.83 → 9.97）。

**短事件跨缝实验**（`d06_event_split.csv`）：1.2 s 短事件放在 t = 6.0 s，使窗口边界穿过事件：

| 窗长 W / s | S = W 最大覆盖率 | S = W/2 最大覆盖率 |
|---:|---:|---:|
| 1.0 | 0.50 | 0.83 |
| 1.5 | 0.50 | 1.00 |
| 2.0 | 0.50 | 1.00 |
| 3.0 | 0.50 | 1.00 |

结论：`S = W`（不重叠）会把短事件劈成两半，单窗最多只覆盖约一半能量；`S = W/2`（50% 重叠）
总有一个窗口完整覆盖事件，验证讲义推荐的工作点。

## 7. D07 混叠实验

真值信号 `2.8 Hz`，采样率依次取 `50 / 5 / 3 / 2 Hz`（`d07_summary.json`、`figures/d07_alias.png`）：

| fs / Hz | Nyquist / Hz | 谱主峰 / Hz | 标准折叠 / Hz | 关于 fs 的镜像 / Hz |
|---:|---:|---:|---:|---:|
| 50 | 25.0 | 2.80 | 2.80 | 47.20 |
| 5 | 2.5 | 2.20 | 2.20 | 2.80 |
| 3 | 1.5 | 0.20 | 0.20 | 2.80 |
| 2 | 1.0 | 0.80 | 0.80 | **1.20** |

失效链（现象 → 指标 → 谱 → 采样率）：

1. **现象**：真实快走约 2.8 Hz 被低采样率记录后，计步结果少算约一半；
2. **指标**：主峰频率从 2.8 Hz 折返到 0.8 Hz；
3. **谱**：单边频谱在混叠频率处出现假峰，真实 2.8 Hz 已无法分辨；
4. **采样率**：`fs = 2 Hz` 低于 `2 × 2.8 = 5.6 Hz`，违反奈奎斯特定理。

关于 `1.2 Hz`：标准奈奎斯特折叠把 `2.8 Hz @ fs = 2 Hz` 折到 `0.8 Hz`；
课程页面给出的 `1.2 Hz` 是 `0.8 Hz` 关于采样频率的镜像（`2 − 0.8 = 1.2`）。
本实验同时输出两者以便对照，并在报告中明确区别，避免把镜像值当成带内混叠频率。

## 8. 作业②：公交防误计步

提出两个**可计算、可验证**的特征：

1. **步频带能量占比** `R = P(0.5~3 Hz) / P(0.5~10 Hz)`；
2. **峰间隔变异系数** `CV = std(步间隔) / mean(步间隔)`。

判据：`R ≥ 0.5` 且 `CV ≤ 0.35` 判为步行。

### 8.1 分状态验证（全部来自本会话真实打点）

| 分组 | 窗口数 | R 中位数 | CV 均值 | 判为步行的比例 | 方差中位数 | 只按方差判为步行的比例 |
|---|---:|---:|---:|---:|---:|---:|
| 步行（正样本） | 398 | 0.880 | 0.068 | **99.25%** | 10.212 | 51.01% |
| 楼梯 | 66 | 0.748 | 0.138 | 84.85% | 5.657 | 10.61% |
| 骑行（负样本） | 82 | 0.105 | 0.245 | **6.10%** | 4.712 | 37.80% |
| 电梯（负样本） | 35 | 0.225 | 0.299 | 14.29% | 0.148 | 0.00% |
| 静止（负样本） | 10 | 0.075 | 0.175 | 10.00% | 0.102 | 0.00% |
| 仿真车辆振动（参考） | 39 | 0.019 | 0.292 | 0.00% | — | — |

结论：双特征把 99.25% 的真实步行窗口判为步行，同时把 93.90% 的真实骑行窗口排除在外。

### 8.2 为什么不能只用“加速度大 / 方差大”

方差基线取步行与车辆振动方差中位数的中点（`10.12 m²/s⁴`）：

- 真实步行窗口**只有 51.01%** 被判为步行——方差把一半真实步行漏掉；
- 仿真乘车窗口仍有 **41.03%** 被判为步行——同时又把乘车误当成走路；
- 换一个更直观的例子：骑行段的**动态峰值 11.09 m/s² 比步行段 8.50 m/s² 还高**，
  只按“动得多大”判断会把骑车当成剧烈步行。

真正拉开差距的是**能量分布与节奏规律性**：骑行段 ZCR 中位数 51.75 次/秒，
是步行段 4.50 次/秒的 11.5 倍，说明车辆/车架振动的高频成分远多于人体步态；
而步行的能量高度集中在 0.5~3 Hz 步频带内（`R = 0.880`），骑行的能量被 3 Hz 以上成分稀释（`R = 0.105`）。

### 8.3 已知边界与待办

- 本会话**没有真实乘车/公交段**，所以“防公交误计步”的正样本是真实步行，
  负样本是**真实骑行段 + 仿真车辆振动**；
- 骑行段的 R 很低是因为其能量集中在 3 Hz 以上；若换成发动机振动更集中的车型，
  低频谱峰可能落进步频带，届时需要再引入第三个特征（ZCR、GPS 车速或步数与位移一致性）。
- 车辆振动目前是仿真参考信号，真实公交/网约车段的阈值仍需复标。

相关图：`figures/bus_features.png`（特征散点与分布）、
`figures/walk_vs_bike_spectrum.png`（步行 vs 骑行时域 / 频域对照）；
原始数据：`bus_summary.json`。

### 8.4 与课程要求的对应

作业②原文只要求“想两个特征”，本报告在此之上补了三条更强的证据：
① 用**自己采的**步行段与骑行段给出特征分布；
② 用真实数据说明“加速度大 / 方差大”为什么不够（骑行峰值高于步行、方差阈值双向失效）；
③ 明确写出两个特征**在什么情况下会失效**，以及需要补什么第三个特征。

其他技术局限：

- 静止段只有 20.0 s（10 个窗口），样本偏少，静止/电梯的统计量置信度低于步行段；
- 加计 115.04 Hz 与陀螺 46.02 Hz 不同频，跨传感器融合前必须显式重采样；
- `Δf = 0.25 Hz` 的格点量化让步频读数只能落在 15 步/分的格点上；
- 打点由人工按下，存在秒级时刻误差（本次最大映射偏移 4.25 ms，可忽略）；
