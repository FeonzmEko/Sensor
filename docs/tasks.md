## 3. 操场试采 10 分钟

> 当前状态：双传感器同步采集器已实现，并完成 62.5 秒真机短测；下一步是执行操场 10 分钟正式试采。

### 3.1 实现同步原始数据采集

- [x] **增加采集控制功能**
  - [x] 在应用页面增加“开始采集”和“停止采集”入口，并显示当前采集状态与样本数。
  - [x] 为每次采集创建独立会话目录，目录名包含日期和时间。
  - [x] 停止采集时执行 `flush`、关闭文件、注销监听器，并保存会话元数据。
- [x] **同时注册加速度计与陀螺仪**
  - [x] 获取 `Sensor.TYPE_ACCELEROMETER` 和 `Sensor.TYPE_GYROSCOPE`。
  - [x] 在同一会话中注册两种传感器，可共用一个 `SensorEventListener`，也可使用两个独立监听器。
  - [x] 两个传感器均使用明确的采样档位；默认沿用 `SensorManager.SENSOR_DELAY_GAME`。
- [x] **保存原始采样点**
  - [x] 每次 `onSensorChanged()` 都保留原始 `SensorEvent.timestamp`，不得用格式化时间替代。
  - [x] 加速度计 CSV 保存 `timestamp_ns,x_m_s2,y_m_s2,z_m_s2`。
  - [x] 陀螺仪 CSV 保存 `timestamp_ns,x_rad_s,y_rad_s,z_rad_s`。
  - [x] 采集阶段不做滤波、插值、坐标旋转、单位换算或降采样，保证原始数据可追溯。
- [ ] **保存采集元数据**
  - [ ] 保存设备型号、Android 版本、应用版本和采集会话编号；应用版本字段待补充。
  - [x] 保存两种传感器的名称、厂商、版本、量程、分辨率和申请采样档位。
  - [x] 保存单位与坐标轴定义：加速度 `m/s²`、角速度 `rad/s`、Android 设备机体系 X/Y/Z。
  - [ ] 保存开始/结束墙钟时间、步行方式、设备放置位置和朝向。
- [ ] **保证采集过程不中断**
  - [x] 10 分钟采集期间保持采集页面在前台；当前方案同时设置页面常亮。
  - [x] 当前正式采集方案要求页面保持前台，因此未开放熄屏或后台采集。
  - [ ] 发生异常或应用退出时，已写入数据应可恢复，并记录异常信息。
- [x] **完成构建与安装验证**
  - [x] 通过 `testDebugUnitTest` 和 `assembleDebug`。
  - [x] 将新 APK 安装到真机并完成冷启动验证。

### 3.2 完成双传感器短测（已通过）

- [x] 确认两个文件的时间戳持续增长，停止后监听器已注销。

### 3.3 完成操场匀速步行试采

- [ ] 正式采集前检查手机电量、可用存储、应用前台状态和设备时间。
- [ ] 固定手机放置位置与朝向，并记录为“手持”“腰包”等具体方式。
- [ ] 点击开始后，先保持静止 10～20 秒，作为静止噪声和漂移检查区段。
- [ ] 在操场或开阔场地以正常匀速步行方式连续采集至少 10 分钟，不可分段拼接。
- [ ] 全程不退出应用、不熄屏、不切换应用，不改变手机放置方式。
- [ ] 停止后立即记录采集开始时间、结束时间和步行方式，并检查两个文件均非空。

### 3.4 检查数据质量

- [ ] 分别统计加速度计和陀螺仪的样本数、持续时间和实测频率。
  - [ ] 实测频率按 `(样本数 - 1) / (最后时间戳 - 第一时间戳)` 计算，时间戳换算为秒。
- [ ] 检查时间戳是否严格单调递增，统计重复值、回退值和长间断。
- [ ] 统计相邻时间间隔的中位数、P95 和最大值，判断是否存在明显丢包。
- [ ] 抽查加速度量级是否为 `m/s²`，静止合加速度是否接近 `9.81 m/s²`。
- [ ] 抽查陀螺仪量级是否为 `rad/s`，静止时是否接近 `0 rad/s`。
- [ ] 核验 X/Y/Z 坐标轴方向是否符合 Android 设备机体系定义。
- [ ] 观察并记录噪声、漂移、异常尖峰等传感器通病，说明是否影响后续特征工程。

- [ ] 论文中使用本人采集的数据，并保留数据来源说明。
